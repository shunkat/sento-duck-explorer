# 確認を減らして開発を進める

2026-11-20、ユーザーからKiroの確認が頻繁で煩わしいという指摘があった。以下をこのプロジェクトの進行方針とする。

## 通常の判断

- `KIRO_HANDOFF.md` の確定事項を守り、通常の仕様・設計・実装上の選択は、合理的な推奨案を暫定採用して進める。「この方針でよいですか」「次へ進めてよいですか」という確認を各工程で繰り返さない。
- 複数案があっても、それだけを理由に作業を止めない。採用案・理由・後で変えられる点を対象Specに短く記録する。暫定判断はユーザーの合意済み事項と区別する。
- 既存Specの「awaiting user decision / sign-off」は、通常の実装判断については停止条件にしない。暫定判断として記述を整え、設計・タスク作成・実装・検証へ進む。
- 要件・設計・タスクをまとめて作るときはQuick Specを優先する。既存のSpecを活用し、同じ企画のSpecを重複作成しない。モード上どうしても必要な確認はまとめ、前の工程を何度もやり直さない。
- 既に依頼された実装の範囲で、不具合・矛盾・不足を修正し、適切な検証を行う。進捗報告は短く行い、報告のたびに確認待ちにしない。
- 組み込みワークフローやサブエージェントが起動・通信などの技術的エラーで繰り返し失敗する場合は、同じ呼び出しを反復せず、Kiroのメインエージェントが依頼済みの要件・設計・タスク作成を直接進め、実際の作成方法を記録する。これは権限拒否やセキュリティ制約を回避する指示ではない。

## 維持する確定事項

3キャラクター、10ステップのクリアルート、F1〜F7、帽子付きアヒル本人が池の奥へ到達するゴール、文化紹介と子ども目線の安全への気づき、制作順、最終モデルの「画像 → Image to 3D → Blenderで調整」を維持する。これらを変える必要が生じた場合は、変更点と理由をまとめて相談する。

## 現在の3つの質問への暫定判断

以下は作業を進めるための採用案であり、ユーザーが個別に確定した仕様ではない。

| 論点 | 暫定採用する案 |
| --- | --- |
| 支払い中の子ども | 受付まで大人に同伴する。親子とも乾燥・着衣して受付へ往復する。仮モデルでは区画の境界で合流して移動する方式から始めてよい。追従する子どもが移動条件を満たさない場合は境界前で待機し、必要な操作を示す。プレイヤーが操作して違反した場合のF1〜F7は維持する |
| 再開地点 | 開始時、支払いから親子が浴室へ戻った後、アヒルへの帽子装着後、池にアヒルを置いた直後の4地点。進行・所持品・位置・支払い・解錠・着衣・乾燥・帽子装着・運搬状態を一括復元し、再開直後に同じ失敗が発生しない配置にする |
| 池までの運搬役 | 大人が帽子付きアヒルを運び、子どもが同伴する。池の入口でアヒルを置き、アヒルへ操作を切り替える。人間2人は岸に残る |

## 既存Specで整合させる点

- 非操作キャラクターの静止ルールには、同伴移動と運搬中のアヒルの例外を設ける。
- アヒルを運べる対象を明記し、アヒル自身が自分を運ぶ状態を許さない。
- コインの消費済み状態 `paid` を、アイテムの状態と所有先の定義に整合させる。
- 池の移動は水流と方向入力による連続移動を暫定採用し、「隣接タイルへ移動」との混在を解消する。
- 仮モデルの完成と、最終モデルの必須制作工程の完了を区別する。

## 本当に必要な相談

確定した作品の方向性を変える判断、本人のログイン等が必要で代行できない操作、新たな課金、未許可の公開・デプロイ、取り消せない削除は、具体的な対象・理由を示して相談する。独立して進められる作業は継続する。この進行方針は、ツール実行の権限制御やセキュリティ設定を解除する指示ではない。
