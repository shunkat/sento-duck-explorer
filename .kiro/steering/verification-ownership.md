# 検証の担当と結果の再利用

2026-11-20、ユーザーは別セッションとKiroの検証重複を減らすよう依頼した。この文書を検証分担の正とし、以前の「Crewが通常操作を検証」「Webが毎回ブラウザーを検証」という指示を以下へ更新する。受入条件や独立レビューは省略しない。

## 担当を一つにする

| 担当 | 実施すること |
| --- | --- |
| Crew A | 実装、必要な自動テスト・ビルド・公開検査。対象コミット、コマンド、結果、残課題をまとめて渡す |
| Crew B | 受入条件と差分の独立レビュー、Aの検証範囲と結果の確認。指摘の再現、証跡不足、変更の影響箇所に絞って追加検証する |
| 既存のCodex実装監督セッション | 通常入力の実プレイとその結果の記録。素材制作と公開前の確認も引き続き担当する |
| Crew Conductor | 作業ごとの担当・対象コミット・検証範囲と引き渡しを管理し、同じ作業を別担当へ重ねて依頼しない |
| Kiro Web | PR #1〜#3のレビューと各PR内の修正・必要な検証。Crew/PR #4の実装や通常入力の通しプレイを重複して開始しない |

- 同じ版の全テスト・ビルド・通しプレイを、A、B、Codex、Webが順番に一式やり直す運用にしない。Bは自分でコードと受入条件を評価する。実行しなかった検証を「再実行成功」と書かない。
- Codexの追加コードレビューは、Bの未解決指摘、Bが確認できない専門領域、Bの中断を補う場合に限定する。同じ差分へのレビュー担当を理由なく増やさない。
- ブラウザー検証がWeb/Crewに必要な場合は、目的と不足するシナリオを現在の実プレイ担当へ渡す。担当を移す場合は現担当の操作終了と引き渡しを確認してから始める。ツールを使えることだけを再検証の理由にしない。

## 引き渡しと固定

1. Aは必要な検証とローカルコミットを完了し、Bへ差分・結果・残課題を渡す。Bの必須指摘は修正し、修正に必要な検証と再レビューを行う。
2. 実プレイの開始前にConductorと担当が、担当名・ブランチ・対象コミット・シナリオ・サーバーを一度確認する。PR #4の現在の実プレイ担当は既存のCodex実装監督セッション。別の最適化・調査セッションはブラウザーを操作しない。
3. 実プレイ中は対象worktreeのソース、素材、依存関係、文書、HEADと開発サーバーを固定する。他担当はそのworktreeの編集、checkout/merge、npm ci、ビルド、再起動、ブラウザー操作をしない。検証中の指摘は私用の引き渡し記録へ残し、担当の停止確認後に直す。
4. 他の許可済み作業を進める場合は、検証対象へ影響しない別worktree・別サーバーを使い、同じ機能を重複実装しない。新規の並列担当や監視ループを、この分担整理だけを理由に増やさない。
5. 実プレイ担当は完了・中断・残課題を返して操作権を解放する。検証結果の文書化とpush前確認は引き渡し後にまとめる。結果待ちだけの自動goal・ナッジを回し続けない。

## 再検証する範囲

| 変更・状況 | 検証 |
| --- | --- |
| 文書・担当指示だけ | 差分・参照先・公開検査。ゲームのテスト、ビルド、実プレイは繰り返さない |
| 限定的な表示・入力・ロジック修正 | 必要な自動テストと影響する操作・表示を確認。関連しない既存結果を繰り返さない |
| 移動、水域、受け渡し、進行など全ルートに及ぶ変更 | 自動回帰と通常入力の全ルートを実プレイ担当が一度確認。失敗条件・復元は変更の影響範囲と不足分を追加する |
| 重大な不具合、検証記録不足、環境差の影響が不明 | 再現・不足する検証を指定する。全体に影響するなら全検証を行い、範囲を広げた理由を残す |

- 実行記録は対象コミット、実行者、日時、対象範囲、結果、未実施範囲を残す。自動テスト、独立レビュー、通常入力、状態注入を区別する。
- 別コミットへ結果を引き継ぐときは、元の検証コミットを維持し、ソース・素材・依存関係・ビルド設定・実行環境の差と影響を確認する。根拠なく新しい版で実行済みとしない。
- PR #4の版別実績は同ブランチの `docs/shoulder-view-verification.md` を参照する。mainや古いSpecの未チェック項目だけを見て既存の通しプレイを再依頼しない。未マージの実績をmainで確認済みとも扱わない。
- 例えば水上移動を変えた版へ、変更前の全ルート成功をそのまま流用しない。実行結果は担当が記録する。

この分担は検証の重複を減らすためのもので、未実装・不具合・未確認の受入条件を完了扱いするものではない。マージ、デプロイ、提出、権限、課金について既存の許可範囲は変えない。
