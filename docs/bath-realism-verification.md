# Bath realism pilot — 2026-11-23

## Scope and ownership

The user approved keeping Duck's appealing rubber-toy character while making the
sento more believable, and authorized Codex to implement this batch temporarily.
Work is isolated on `feat/bath-realism`, based on `aac8557`. Codex authored the
changes and one independent Codex reviewer checked them. This is not new Kiro
execution or evidence of hackathon submission/category acceptance.

The pilot adds scoped ceramic grout relief, varied wet-floor roughness, moving
water normals and a bounded Duck wake, two warm local lights, ceiling/window
faces and soft contact shading. The shared reflection probe and ACES exposure
also affect other rooms; their appearance remains on the final check list.

No original GLB, third-party asset, game rule, collision envelope, route, input
binding or dependency manifest changed. The small textures are generated by
original runtime code; there is no new downloaded asset or rights dependency.
The window is a flush presentation face, not a new passage. Contact shading is
an approximation, not baked global illumination or a shadow-map pass. Reflections
come from a static authored room probe, not a live reflection of moving objects.
Refraction, steam, sound and new character animation are not part of this pilot.

## Original final-check list

The implementation handoff followed `.kiro/steering/verification-ownership.md`
and reserved one combined final normal-input check until implementation and
required review fixes were complete. No browser play was performed during that
implementation stage, and no previous FPS or playthrough result was claimed for
the new renderer configuration. The checklist handed to final verification was:

1. Compare the same main-bath Duck view, washing close-up and wide bath view with
   the base version; confirm the new look is visibly better at actual game size.
2. Swim, stop, turn and restore: reflections/wakes stay subtle, decay at rest and
   do not cross vessel edges or survive restoration/growth.
3. Inspect grout at oblique angles, wet/dry transitions, ceiling/window placement,
   contact attachment and the minimap/overview boundary.
4. Check white soap/towels, yellow Duck, faces, posters, captions, sauna, changing
   room and outdoors for darkening, glare or readability changes from ACES/probe.
5. Inspect actual shader errors, draw calls and frame intervals on standard and
   lightweight settings; phone GPU/heat/performance remains unverified.
6. Complete one Duck → Child → Adult → street route, grouping the needed failure
   and restart spot checks in the same slot. Preserve the worktree, HEAD, server
   and browser during that check, and fix only discovered local issues afterward.

The visual standard must be evaluated before extending this treatment to the
remaining facilities. The release observations and remaining limits follow.

## Daylight correction after feedback — 2026-11-23

The user reported a dark atmosphere in published `59c3e42` and requested an
adjustment. Codex raised the static room-probe bounce and changed the hemisphere
ground contribution from blue-gray to pale warm tile. The high window now emits
soft light using one Three.js RectAreaLight; the two local ceiling lights are
lower and gentler. ACES exposure remains 1.12. Geometry, GLBs, game rules, input
and dependencies are unchanged. Existing Three.js LTC lookup data increases the
main bundle from 700.32 to 949.50 kB (gzip 187.75 to 293.44 kB); there is no new
shadow-map or reflection pass. Phone/GPU performance has not been measured.

The correction passed **411 tests across 45 files**, the repository-base build,
source/distribution publication scans and whitespace checks. One independent
code reviewer reported no required findings. The added lighting test checks
the emitting direction against the window, placement, and shared LTC ownership.

bath at 1280×720 in Mac Chrome. This is feedback correction after the prior
